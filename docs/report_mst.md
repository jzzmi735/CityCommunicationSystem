> 对应题目第（1）问

---

## 1. 图模型

### 1.1 问题抽象

题目要求为若干城市设计通信网络，使得任意两个城市之间都可以（直接或经多跳）通信，
并且建设总造价最低。这个问题可以抽象为**无向连通带权图上的最小生成树（MST）**问题。

抽象方式：

| 现实对象 | 图论概念 |
|---|---|
| 城市 | 顶点（vertex），编号 `0, 1, 2, ..., n-1` |
| 两城市之间的通信链路 | 无向边（edge） |
| 建设成本 | 边权（weight） |
| 通信网络 | 生成树（含所有城市且无回路） |
| 最低总造价 | 最小生成树的权值之和 |

### 1.2 为什么是生成树

- 网络中必须让 `n` 个城市全部连通，因此至少需要 `n-1` 条链路；
- 如果链路数超过 `n-1`，根据图论必然出现回路，回路上的任意一条边都可以删除
  （因为回路上剩余部分仍保证连通），所以回路只会增加造价而不带来收益；
- 因此最优方案一定是**恰好 `n-1` 条边且无回路**的结构，即生成树。

由于任意两个城市之间都可以建设链路，本题大概率是**稠密图**，因此存储结构
选用邻接矩阵而不是邻接表。

### 1.3 存储结构

```cpp
class MSTService {
private:
    int n_;                                   // 城市数量
    std::vector<std::vector<int>> cost_;      // 邻接矩阵
};
```

约定（与《共同开发规则和接口》§8.1 一致）：

```text
cost_[i][i] == 0           对角线为 0
cost_[i][j] == INF         两城市间没有直接链路
cost_[i][j] == cost_[j][i] 无向图必须对称
INF == 0x3f3f3f3f
```

`setCost(from, to, cost)` 会**同时写入** `cost_[from][to]` 与 `cost_[to][from]`，
从接口层面保证无向图对称性，调用方（GUI）不需要自己保证。

## 2. 最小生成树定义

设 `G = (V, E, w)` 为无向连通带权图，`|V| = n`。`G` 的生成树是满足以下条件的子图 `T`：

1. `T` 包含 `V` 中全部顶点；
2. `T` 连通；
3. `T` 无回路。

由 1、2、3 可推出 `T` 恰有 `n-1` 条边。

**最小生成树**是使 `w(T) = Σ_{e∈T} w(e)` 最小的生成树。

两个关键性质支撑 Prim 和 Kruskal 的正确性：

**性质 1（切割性质）**：对任意一种把顶点分成两部分的切割，横跨该切割的最小权边
一定属于某棵最小生成树。Prim 正是反复利用该性质。

**性质 2（回路性质）**：对图中任意回路，回路上的最大权边一定不属于任何最小生成树。
Kruskal 正是反复利用该性质。

> 若图不连通，则不存在生成树。本模块统一返回
> `success = false`、`errorMessage = "Graph is disconnected"`。

---

## 3. Prim 思想

Prim 算法遵循**“从一个城市出发，逐步把最近的城市拉进城”**的贪心策略：

1. 任选一个起始城市 `startCity`，把它放入生成树集合；
2. 反复执行：在所有“一端在树内、一端在树外”的边中，选权值最小的一条，
   把对应城市拉入树内；
3. 重复 `n-1` 次后，树内包含全部城市，所选边构成最小生成树。

正确性依据是**切割性质**：树内顶点与树外顶点构成一个切割，其最小横跨边必然安全，
可以加入 MST。

---

## 4. Prim 流程

时间复杂度 `O(n^2)`，使用邻接矩阵与三个辅助数组：

```text
minCost[v]  城市 v 到当前生成树的最小边权（初始为 INF）
fromCity[v] 该最小边来自树内哪个城市（用来还原边）
inTree[v]   城市 v 是否已加入生成树
```

流程：

```text
输入：城市数 n，邻接矩阵 cost，起始城市 startCity

1. 校验 n > 0、0 <= startCity < n，否则返回失败
2. 若 n == 1，成功返回（0 条边，总造价 0）
3. 若图不连通，返回失败
4. minCost[startCity] = 0
5. 重复 n 次：
   a. 在 inTree == false 的城市中，找 minCost 最小者 best
   b. 若不存在或 minCost[best] >= INF，说明不连通，返回失败
   c. inTree[best] = true
   d. 若 best != startCity，把边 (fromCity[best], best, minCost[best]) 加入结果
   e. 用 best 更新所有树外城市的 minCost / fromCity
6. 返回选中边、总造价、运行时间
```

实现见 `src/mst/MSTService.cpp` 的 `MSTService::prim`。

**边界处理**：

- 非法起点（`startCity < 0` 或 `>= n`）返回失败，不崩溃；
- 非连通图返回失败；
- 单城市返回成功且总造价为 0；
- 起点不同不影响**总造价**（测试 3 对 6 个起点逐一验证）。

## 5. Kruskal 思想

Kruskal 算法遵循**“按造价从低到高挑边，只要不成环就要”**的贪心策略：

1. 把图中所有边取出来，按权值升序排序；
2. 依次考察每条边，若它的两个端点当前不属于同一连通分量，则选入该边
   （不会成环），否则丢弃；
3. 选满 `n-1` 条边即得到最小生成树。

正确性依据是**回路性质**：按升序处理时，若一条边的两端已连通，说明它与已选边
构成回路，而它是回路上权值最大的（因为更大的边还没被处理），故可以安全丢弃。

---

## 6. 并查集（DSU）

Kruskal 需要快速回答“两个城市当前是否已连通”，这正是并查集的用途。

本模块把并查集实现为 `MSTService.cpp` 的**匿名命名空间内部类**，
不暴露给 GUI（GUI 完全不需要知道它的存在）。

```cpp
class DisjointSet {
public:
    explicit DisjointSet(int n);
    int find(int x);              // 路径压缩
    bool unite(int a, int b);     // 按秩合并，返回 false 表示已在同一集合
private:
    std::vector<int> parent_;
    std::vector<int> rank_;
};
```

两个优化：

- **路径压缩**：`find` 过程中把沿途结点直接挂到根上，后续查询接近 `O(1)`；
- **按秩合并**：把矮树挂到高树上，避免树退化成链。

两者结合后，单次操作的均摊复杂度为 `O(α(n))`，其中 `α` 为反阿克曼函数，
在实际数据规模下 `α(n) ≤ 4`，可视为常数。

## 7. 复杂度

设城市数为 `n`，边数为 `m`。

| 算法 | 时间 | 空间 | 说明 |
|---|---|---|---|
| Prim（邻接矩阵） | `O(n^2)` | `O(n^2)` | 选点 `O(n)` 次，每次扫描 `O(n)` |
| Prim（邻接表 + 堆） | `O(m log n)` | `O(n + m)` | 本模块未采用，稠密图无优势 |
| Kruskal | `O(m log m)` | `O(n + m)` | 排序为主，DSU 部分近线性 |
| 连通性检测（BFS） | `O(n^2)` | `O(n)` | 邻接矩阵扫描 |

对稠密图 `m = O(n^2)`：

- Prim：`O(n^2)`
- Kruskal：`O(n^2 log n^2) = O(n^2 log n)`

Kruskal 多出一个 `log` 因子，因此**稠密图上 Prim 更快**。这一点被第 9 节的
实测数据完全证实。

## 9. 两种算法性能比较

测试配置：随机生成的稠密连通图（约 60% 边密度），每个规模运行 5 次取平均，
编译选项 `/O2`，`n = 10 / 50 / 100 / 200 / 500`。

| n | Prim 用时 (ms) | Kruskal 用时 (ms) | Kruskal / Prim |
|---:|---:|---:|---:|
| 10 | 0.002 | 0.001 | 0.7 |
| 50 | 0.019 | 0.063 | 3.3 |
| 100 | 0.051 | 0.141 | 2.8 |
| 200 | 0.152 | 0.548 | 3.6 |
| 500 | 0.757 | 3.262 | 4.3 |

### 结论

1. **小规模（n = 10）两者相当**，`runningTimeMs` 分辨率下都在微秒级，
   排序与建表的常数开销还看不出差异。
2. **规模增大后 Prim 明显更快**。`n = 500` 时 Prim 约 0.76 ms，
   Kruskal 约 3.26 ms，Kruskal 约为 Prim 的 4.3 倍。
3. 这与理论分析一致：稠密图上 Prim 是 `O(n^2)`，Kruskal 是 `O(n^2 log n)`。
   Kruskal 的时间主要花在对 `n(n-1)/2` 条边排序上。
4. **两者结果始终一致**：全部规模下 `totalCost` 完全相同，
   且边数均为 `n-1`（测试 8 逐项断言）。
5. `n = 500` 时两者都在 4 ms 以内，对课程设计规模而言**都可直接用于 GUI 交互**，
   不会造成界面卡顿。

### 工程建议

- 稠密图（本题情形）默认用 **Prim**；
- 稀疏图（如实际城市间仅少数链路）用 **Kruskal** 更合适；
- 两者都保留，可以在界面上让用户选择并对比，正好满足题目“两种算法比较”的要求。
